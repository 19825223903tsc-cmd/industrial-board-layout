# 生图遵循测试

用户已要求实际生图时使用；它是五轮线框审核之后的另一项验收。没有生成输出就记“未测试”，输入被拒绝也不算已生成样本。

## 提交前锁定条件

1. 核对当次工具实际参考上限和能力，不将某次工具的5张限制写成所有工具的永久规则。选定参考后再审查交接包。
2. 参考过多时可整理带唯一编号的源图/已证实裁切图谱，保留原图数据并明确region→图谱单元映射。实际查看图谱，检查小部件和标签仍可辨；主身份图优先单独保留。缩成图谱不等于证据充分，模糊就精简图位或分批，不让模型猜。
3. `generation-inputs.json`可记录实际工具、已知上限、每张输入的path/role/sha256。review_gate会校验上限、角色、文件与指纹；图谱、参考角色、文案或裁切改变都需重新完成五轮。
4. 保存工具实际使用的完整提示词与输入指纹、期望比例、必要图位、身份锁和本次空间容差。容差只用于本次构图遵循实验，不能宣称是精准印刷排版的标准。

## 原始输出评估

保留原始文件、实际像素尺寸与比例，不先拉伸、拼图或后置文字再声称模型遵循。必要时做只用于观察的局部放大或并排对照，标明不是新生成结果。

逐项给出通过/不通过/未确认及具体证据：

- 画布与构图：实际比例、主视觉锚点、各组相对位置/面积、阅读顺序和空白节奏。
- 完整性与对齐：各必要图位是否存在，跨区标题、图片边界和图注基线是否保持；有框没产品也算缺失。
- 产品身份：逐图对照参考的轮廓、部件、连接、开口、屏幕、镜头、材质关系和配置。错误机身、附件混入主机、重建未见结构属于硬失败。
- 取景：局部是否确为指定特征，重要轮廓有没有被裁去或换成相邻部件。
- 同款跨图状态：屏幕界面、按键状态、配件连接等逐图对照各自来源；确认型号相同还不够。主图状态被复制到另一参考图也记为偏差，不能因产品大体相似而放行。
- 文字：对照真实文案，核对遗漏、错字、乱码、重复和图注归属；看不清就未确认，不凭相似字形判正确。
- 引导移除：占位框、X线、源图标记、图谱标签、调试ID不得出现在成品。

不得以构图好看抵消错误产品图，也不以线框对齐报告代替输出检查。未确认项不能标为通过。

## 修正结果分项验收

对每个已观察问题建立“期望关系或状态—当前证据—判定”记录，产品、几何、文字分别给结论。修好屏幕或部件状态不代表图缝、基线也恢复；未执行的修正不能标为通过。OCR结果只用于定位疑点，应先核对识别语言是否实际支持当前文本；候选差异需放大目视，不把识别失败当作无错，也不把OCR误认直接当成生成错字。看不清则未确认。

生成后至少完成三次不同焦点的复核：①构图、图缝和跨区基线；②逐图产品及状态；③实际文案、图注归属和引导移除。逐项记录真实观察和当前输出指纹，不把脚本运行次数当审查。已知失败或未确认项不能包装成“零错误成品”。这三次检查不替代生图前的五轮。

## 修正与复测

一次失败先归因：引导歧义、参考分辨率/映射、文案负担、优先级冲突，或模型执行偏差。若整板编辑只修改了局部内容而保留错误几何，记录这种执行偏差；后续获授权的构图复测可改从审核线框及原图校样重新生成，别仅叠加更强的“严格对齐”措辞。不能从尚未执行的新策略推断成功。针对已观察的主要问题修正，保留旧稿与检查结果。改交接包就重做五轮；不允许只换图注掩盖错误部位。一次任务默认最多做一次有明确目标的修正复测，仍有硬失败则交付测试结论和未通过稿，避免无限生成；用户要求更多测试时继续其明确范围。

一张结果只说明该次表现；基线加修正稿也不能证明稳定性。要声称稳定，须在保存的相同输入条件下多次独立生成，并报告样本数、每项通过数、失败/未确认项，区分同产品重试与跨产品泛化。不能虚构随机种子、后端型号或工具未提供的参数。
