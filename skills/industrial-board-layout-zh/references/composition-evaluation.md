# 构图判断的行为评估

几何脚本验证位置和约定关系，不验证构图是否适合产品。两类结果分别报告。

## 每次构图的判断记录

第一轮审核product_fit应能回答：

1. 哪些实际可见形态、视角、素材条件支持当前视觉锚点与阅读顺序？
2. 相较一种实质不同的组织方式，当前方案解决了什么问题、牺牲了什么？不必额外交付备选图，不强制为明确指定的用户版式另做方案。
3. 哪些区域直接表达产品重点，哪些只是为了填空？删去无作用区域。
4. 如果只有一张图或缺少某个视角，该方案是否还能成立？能否精简，而不是生成不可靠的产品图？
5. 同一产品的目标由外观展示变成操作解释时，构图该如何变，哪些材料实际上还不够？不能仅凭改坐标声称具备适应性。

可在layout.json的intent或qa-review.json的product_fit中记录，避免另造一堆重复报告。

## 评估维度

- 证据适配：每个图位的身份、视角、局部和状态有真实材料支持。无依据新视角属于失败，不因好看而抵消。
- 信息组织：主次、动线与图文分组有内容理由，用户能看懂本板最重要的信息。
- 形态适配：主体比例、朝向和负空间合理；没有为填框而改变产品。
- 语言适配：中英文各自可读，语言变化没有破坏图像归属与层级。
- 素材经济性：少图时能删减和重组，不用虚构过程或重复小图伪装内容丰富。
- 交接有效性：用户要求实际生图时，再看模型是否保持重要关系、目标取景与产品身份。没有执行生图则记为未测试，不能从线框通过推导已有效。

逐项用“通过/不通过/未验证”和具体观察记录，不以一个综合分数掩盖错误产品图。设计审核可以推翻几何通过的方案。

## 待执行案例库

`assets/composition-eval-cases.json`包含不同形态、表达目标与素材稀缺程度的测试条件。它们只是测试题目，没有真实素材、线框或生图结果，不计为已完成的跨产品验证。开始新设计测试时遵守所在环境的初稿留存规则；未被请求的多项目制作或生图不因案例库存在而自动授权。

先对明确提供的真实素材做行为测试；同一产品更换表达重点能检验决策依据。可以补做假设输入模拟，用来发现路由和信息判断问题，报告时标明模拟；真正的泛化验证需要来自不同产品的实际图文输入及结果评审。

不要求每个产品都出现不同构图。相同组织若有充分理由可以成立；无依据地为了变化而变化同样失败。失败修正应聚焦已观察的问题，不把一个案例变成所有产品的固定模板。

## 将审美判断变成可复核的观察

在最终一轮的density_balance中记录以下四项观察；不以“高级、好看、没有问题”代替依据，也不用总分抵消单项失败：

| 维度 | 实际看什么 | 需要修改的情形 |
| --- | --- | --- |
| 疏密与节奏 | 全板缩略图、局部放大；图注到下组、总结到页脚；分区之间留白是否有组织作用 | 连续空白打断阅读、下半区空散、局部拥挤或正文被压缩 |
| 主次与尺度 | 第一眼视觉入口、主图与辅助图的实际主体大小；黑底面板和真实轮廓分别看 | 辅助图抢焦点、主图缺乏识别度、小图仅因源图空边而过小 |
| 阅读顺序 | 按实际版面从入口读到结尾，标题、编号、分组和叙事是否一致 | 修改横竖版后编号跳序、同排内容各自错位、重复图无新的对照作用 |
| 图文归属与视觉一致 | 图边/图注、基线、字体、色调、背景面板是否清楚地建立关系 | 图注像归属另一张图，容器对齐而有效画面不齐，字号/图像表现不一致 |

每项用“通过/需修改/未确认 + 具体区域/现象 + 处理或取舍”记录。无需强行规定每次必须做多个候选，用户要求保持的构图不因评审而被自动换掉。对产品真实性或可读性的明确失败，审美判断必须判失败。

可运行 `python scripts/composition_signals.py --dir <guide>` 生成辅助数据：主辅图框面积、四段几何覆盖、完整空白带、contain比例和源图复用。它不输出审美通过/综合分数；图框覆盖不是视觉重量，深色背景也不是有效产品信息。信号仅帮助找到需要放大查看的区域，不设跨所有产品通用的“合格占比”。没有异常数值也不能省略目视。

若以同一构图多次生图检验稳定性，按 [model-validation.md](model-validation.md) 分别记录各次输入、输出与偏差；不能把一次可用稿称为稳定遵循。
